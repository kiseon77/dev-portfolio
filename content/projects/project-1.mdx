## 프로젝트 목적

수기 및 엑셀 중심의 고객 관리 프로세스를 자동화하여 단기 근무자의 휴먼 에러를 방지하고, 정제된 주문 데이터를 기반으로 정확한 발주 데이터 확보.

## 배경

- **수기 작업의 비효율성** : 현장에서 고객 정보를 종이에 적은 다시 엑셀로 옮기다 보니, 오타가 나거나 데이터가 지워지는 실수가 자주 일어났습니다.
- **단기 근무자의 실수 방지 필요** : 단기 근무자는 학교별 교복 특수성을 외워야했고, 엑셀을 실수로 지우는 일이 많아 인수인계가 어려웠습니다.
- **발주 데이터 취합의 한계** : 일정기간 교복 주문을 받고, 짧은 기간 내에 발주를 해야하는데, 매번 수동으로 수량을 합쳐야해서 시간이 오래 걸리고, 수량이 틀리는 문제가 있었습니다.

## 주요기능

- **예약 우선(Reservation-over-Rejection) 주문·재고 처리**
  - 측정 기간 중에는 주문을 거부하지 않고 예약으로 접수, 측정 종료 후 관리자가 취합해 추가 발주
  - 출고 시 가용 재고만큼 자동 부분 출고 + 부족분은 예약 상태로 분리하는 배치 로직
- **JWT 기반 역할별 인가(RBAC) 및 업무 흐름 연동 권한 분기**
  - admin/staff 역할 미들웨어 인가, 토큰 유효해도 비활성화된 계정은 즉시 차단
  - 측정 진행 중엔 스태프도 수정 가능하지만 측정 종료 후엔 관리자만 수정 가능하도록 단계별 권한 전환
- **주문·학생 변경 이력 추적**
  - 주문 상태 변경, 학생 정보 수정 이력을 자동 기록
  - 관리자가 특정 주문/학생의 변경 히스토리 조회 가능
- **학교·교복 마스터 데이터 관리 효율화**
  - 학교별 교복 세트를 일괄 등록/교체
  - 전년도 설정 복사 기능으로 신규 학교 등록 시 반복 입력 최소화

## 성과

- **엔드투엔드(End-to-End) 개발** : 기획, 디자인, 화면 구현 그리고 생소했던 서버 코드를 보고 확장하는 과정을 혼자 경험하면서 하나의 서비스가 생기는 흐름을 깊게 이해하게 되었습니다.
- **가상 데이터 기반 테스트** : 단기 근무자의 오기입 시나리오를 가성으로 설정해 직접 테스트해보며, 에러를 차단하고 데이터 무결성을 유지하는것을 확인했습니다.
- **발주 자동화 로직 검증** : 가상의 더미 주문데이터를 넣었을때, 모든 아이템 재고 수량이 합산되어 출력되는것을 검증했습니다.

## 프로젝트 회고 및 배운 점

- **비즈니스 이해** : 뽑내기 위한 스택이 아니라, 현장의 불편함을 해소하기 위한 서비스에 맞는 기술을 찾아 나아가는 과정이 가치 있다는것을 깨닳았습니다. 현장의 문제를 정의하고 시스템으로 해결하는 과정에서 개발자로서 큰 보람을 느꼈습니다.
- **AI와의 든든한 협업** : 유일했던 팀원인 백엔드 개발자가 빠지게 되면서, AI를 아키텍처 설계부터 코드 리뷰어까지 개발 전반적인 부분에 사용하게 되는 계기가 됐습니다. 덕분에 모르는 기술 스택 앞에서도 문제를 해결하는 자신감을 얻었습니다.
- **uni size의 과제** : 현재는 가상의 데이터로 데스트했지만, 실제 현장 배포를 진행하면서 피드백을 듣고, 예상하지 못한 엣지케이스를 수집하면서 UI/UX와 서버 로직을 지속적으로 고도화할 예정입니다.
